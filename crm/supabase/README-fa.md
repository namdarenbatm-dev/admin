# راه‌اندازی بک‌اند SNI CRM

این پوشه زیرساخت پایگاه داده PostgreSQL برای SNI CRM را نگه می‌دارد. رابط فعلی CRM روی GitHub Pages است؛ GitHub Pages فقط فایل‌های استاتیک را میزبانی می‌کند و جایگزین API یا پایگاه داده نیست.

## پیش‌نیازهای محیط عملیاتی
1. یک پروژه Supabase در سازمان/حساب مالک سامانه ایجاد شود.
2. آدرس پروژه و کلید عمومی (publishable/anon) برای اتصال مرورگر دریافت شود.
3. فایل `schema.sql` در SQL Editor همان پروژه اجرا و خروجی بدون خطا بررسی شود.
4. اولین کاربر از مسیر دعوت امن Supabase Auth ایجاد شود.
5. رکورد همان کاربر در `public.profiles` با نقش `super_admin` توسط مدیر پروژه ثبت شود.
6. سیاست‌های RLS با حساب‌های آزمایشی هر نقش تست شوند؛ تا پیش از این تست، داده واقعی وارد نشود.

## جداول اصلی
- `profiles`, `regions`, `brokers`: کاربران، مناطق و کارگزاران
- `merchants`, `sales_points`, `terminals`: پذیرنده، نقطه فروش و پایانه
- `terminal_status_history`: تاریخچه تغییر وضعیت چرخه عمر پایانه
- `leads`, `targets`: قیف فروش و اهداف
- `commission_rules`, `commission_ledger`: قواعد و دفتر محاسبات پورسانت
- `daily_transaction_metrics`: تجمیع روزانه تراکنش
- `tasks`, `workflow_rules`: پیگیری و گردش‌کار
- `audit_logs`: ثبت تغییرات

## نقش‌ها
`super_admin`, `sales_manager`, `regional_manager`, `broker`, `bi_analyst`, `operations`, `viewer`

سیاست‌های Row Level Security در اسکیمای اولیه تعریف شده‌اند تا دسترسی کارگزار به محدوده خودش و مدیر منطقه به منطقه مربوط محدود شود. این سیاست‌ها باید در محیط واقعی با حساب‌های آزمایشی و داده غیرحساس بازبینی شوند؛ تعریف SQL به‌تنهایی اثبات‌کننده صحت امنیت عملیاتی نیست.

## مواردی که هنوز برای Go-Live لازم‌اند
- اتصال رابط کاربری به Supabase Auth و جداول (CRUD واقعی به جای localStorage)
- تکمیل کنترل دسترسی سمت سرور و تست نفوذ/RLS
- تعیین منبع رسمی داده تراکنش و ساخت API/فرآیند import امضاشده
- تعریف فرمول‌های قطعی پورسانت، KPI، رتبه‌بندی و قواعد تأیید با مالک کسب‌وکار
- زمان‌بندی هشدارها و گردش‌کارها در سمت سرور
- پشتیبان‌گیری، مانیتورینگ، ثبت خطا، سیاست نگهداری داده و محیط staging
- تست پذیرش با داده نمونه و تأیید نهایی مالک سامانه

**هشدار:** هرگز کلید `service_role` یا رمز پایگاه داده را در کد مرورگر، GitHub Pages یا مخزن عمومی قرار ندهید. فقط کلید عمومی قابل انتشار است و آن هم باید همراه با RLS صحیح استفاده شود.

- Region: `eu-central-1` (Frankfurt)

- رابط وب از کلید **publishable** استفاده می‌کند؛ این کلید عمومی است و کلید secret یا service_role در کد مرورگر قرار نگرفته است.
- فایل تنظیمات عمومی: `crm/config.js`

### راه‌اندازی اولین مدیر
1. در Supabase Dashboard پروژه `sni-crm` را باز کنید.
2. به Authentication > Users بروید و اولین کاربر سازمانی را با ایمیل و رمز عبور ایجاد کنید.
3. Trigger پایگاه داده به‌صورت خودکار پروفایل اولیه با نقش viewer می‌سازد.
4. اولین کاربر وارد CRM شود؛ تابع محدود `bootstrap_first_admin` فقط در صورت نبود super_admin، همان حساب اول را به super_admin ارتقا می‌دهد.
5. پس از آن، کاربران بعدی مدیر نمی‌شوند و نقش آن‌ها باید توسط مدیر سامانه تعیین شود.

### وضعیت اتصال رابط
- ورود با Supabase Auth: پیاده‌سازی شده.
- دریافت و ثبت و حذف کارگزاران: متصل به جدول مرکزی `brokers`.
- محدودیت دسترسی داده‌ها: RLS در دیتابیس اعمال می‌شود.
- سایر ماژول‌ها هنوز به CRUD مرکزی متصل نشده‌اند و نباید عملیاتی تلقی شوند تا اتصال و آزمون مستقل آن‌ها تکمیل شود.
